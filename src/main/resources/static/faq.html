Frequently Asked Questions

Everything you need to know about using the Student Management System.

Administrative authentication is required for all write and update operations across /api/v1/students/**. By default, the system provisions an administrator user with the username admin and password configured via the ADMIN_PASSWORD environment variable (default: admin123). You can log in via the Login page or pass standard HTTP Basic credentials in API headers.

Every student record requires a unique Roll Number and unique Email Address. Phone numbers, if supplied, must be exactly 10 digits (e.g. 9876543210). The Year of Study must be between 1 and 4, and the Date of Birth must be a past date. Duplicate roll numbers or emails immediately trigger a 409 Conflict error with clear feedback.

The search bar on the Dashboard communicates directly with /api/v1/students/search. Keystrokes are debounced by 350ms to minimize network requests. It performs a case-insensitive partial match across first names and last names, and seamlessly combines with Department and Year of Study dropdown filters while preserving pagination.

You can use the following power shortcuts:
• / – Instantly focus the student search bar.
• n – Open the New Student enrollment modal.
• d – Toggle between Light and Dark mode.
• ? – Show the Keyboard Shortcuts help dialog.
• Esc – Dismiss any open modal dialog or mobile menu.
Shortcuts are automatically bypassed while typing inside text fields.

Click the 🌙 / ☀️ icon in the navigation bar or press the d key anywhere on the page. The system automatically detects your operating system's prefers-color-scheme on first load and persists your manual selection in localStorage for future visits.

Run docker compose up --build in the repository root. This orchestrates two isolated services: a production mysql:8.0 database with data volumes and healthchecks, and the multi-stage packaged sms-backend container running Eclipse Temurin 21 JRE as a secure non-root user on port 8081.

Every student endpoint resides under /api/v1/students. Use standard HTTP Basic authentication headers: -u admin:admin123. The API provides predictable status codes (201, 200, 204, 400, 404, 409) and a standardized JSON ErrorResponse envelope containing timestamps, status, error details, and per-field validation error maps.

This application uses minimal browser storage solely for functional operation: sms_theme (preserves dark/light appearance), sms_cookie_consent (stores your cookie decision), and secure session tokens for authenticated administrators. No personal data is tracked or transmitted to external advertisers or third parties.
